# Разработка и сборка

C# / WinForms. Менеджер использует .NET Framework 4.8. Готовая программа собирается в один EXE со встроенными помощниками x86/x64.

## Перед изменениями

Прочитай [AGENTS.md](../AGENTS.md), [состояние разработки](../DEVELOPMENT-STATE.md) и описание текущего выпуска. Сохраняй пользовательские изменения и тексты.

## Локальная сборка

Из корня проекта в Windows PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Build-OneFileRust.ps1 -OutputDirectory .\bin
```

`Bypass` действует только на запускаемый процесс. Сборка по умолчанию без подписи. Reference assemblies подготавливаются скриптом автоматически; при первом запуске может требоваться сеть.

Релиз для владельца собирай по [инструкции по подписи](../SIGNING.md) в один EXE со встроенными рабочими настройками. В итоговом сообщении укажи папку C:\ServiceManager3000\releases. EXE на GitHub загружает владелец вручную.

## Проверки

`Test.ps1` и целевые сценарии находятся в `tests`. Полный сценарий содержит проверки, требующие подготовки среды: не запускать реальные установки и системные изменения на рабочем компьютере. Условия и ограничения перечислены в [состоянии разработки](../DEVELOPMENT-STATE.md).

Для последних изменений комплекта и инструкции используй `Test.ps1 -BundleWorkflow`. Сценарий проверяет распознавание папок, окно выбора, два источника, сохранение вложенных путей, сенсор и отображение встроенной инструкции. Для живой проверки Яндекса скачай установщик и архив в изолированную папку без запуска. Сверь относительный путь, формат и SHA-256. Для многостраничного каталога Google Диска задай ключ Drive API в окружении как `BARS_GOOGLE_DRIVE_API_KEY`. Для проверки узких экранов с фиксированным числом пикселей запусти `Test.ps1 -LayoutAudit`.

## Выпуски

В черновик GitHub прикрепляй RELEASE-версия.md и CHANGELOG.md. Подписанный Bars.Automation.Manager.<версия>.exe передавай владельцу из папки releases для ручной загрузки. В репозитории хранятся исходники, ресурсы и тесты.
